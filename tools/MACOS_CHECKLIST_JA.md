# macOS 実機チェックリスト

macOS 向けの修正はすべて Windows 上で書かれており、Objective-C / cgo 部分は一度もコンパイル・実行されていません。
GitHub に push すると `.github/workflows/ci.yml` が macOS ランナーでビルドし、`syki-macos-<sha>` として .app を成果物に出します。
初回起動は `xattr -dr com.apple.quarantine syki-sok.app`（macOS 15 以降は システム設定 → プライバシーとセキュリティ →「このまま開く」、14 以前は右クリック →「開く」）が必要です。

## 0. まず CI が通るか

- [ ] macOS ジョブの `go build ./...` が成功する
  - 失敗箇所が `hotkey_darwin.go` の場合: そのファイルを削除し、`window_darwin.go` 側で `updateGlobalHotKeyNative` を `return false` のスタブにすれば他は生きます
  - `window_darwin.go` の場合に疑う順: `-fobjc-exceptions` と `@try/@catch` → `(NSWindow *)nsWindow` のキャスト → `setValue:forKey:@"drawsBackground"`
  - `use of undeclared identifier 'kAEQuitReason'` の場合: `#import <CoreServices/CoreServices.h>` が効いていません。`kAEQuitReason` を整数 `0x7768793F`（`'why?'`）に置き換えれば通ります
  - `sykiGoQuit` の未定義・型不一致の場合: `openfile_darwin.go` の `//export sykiGoQuit`（戻り値 `C.int`）と `window_darwin.go` の `extern int sykiGoQuit(void);` を突き合わせる
- [ ] ログの `lipo -archs` が `x86_64 arm64` になっている（片方だけならユニバーサル化に失敗してフォールバックしています）
- [ ] `plutil -lint` が OK
- [ ] `tools/crosscheck.ps1`（相当の手順: `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go vet ./...` / `go test -c`)で、cgo を使わない純 Go 部分（`platform_darwin.go` など）は Windows 上でも型チェックできるようになりました。CI の Windows ジョブにも同じクロスチェック手順(`.github/workflows/ci.yml` の "Cross-check macOS build (no cgo)")が入っています。Objective-C / cgo 側(`window_darwin.go`、`hotkey_darwin.go`)は引き続きこの macOS ジョブでしか検証できません

## 1b. 終了の経路（⌘Q / Dock / ログアウト）

⌘Q・メニューの「Quit syki::sok」・Dock の「終了」は、ページにセッションを保存させてから `App.CloseWindow` と同じ経路で終了するようになりました。ログアウト・再起動・システム終了のときだけは止めずに AppKit に終了させます。

- [ ] 何か入力した直後（0.5 秒以内）に ⌘Q → 再起動すると、最後の入力まで残っている（未保存タブ・新規タブの両方）
- [ ] ⌘Q 後に `~/Library/Application Support/syki-sok/ipc-session.json` が消えている。`lsof -i :41739` が空
- [ ] メニューバーの「syki::sok ▸ Quit syki::sok」でも同じ（入力が残る・ipc-session.json が消える）
- [ ] Dock アイコンを右クリック →「終了」でも同じ。消えていなくても（Dock が終了理由を付けて送る場合）終了すること自体は必須
- [ ] ⌘Q を連打しても 1 回だけ終了し、エラーダイアログやクラッシュレポートが出ない
- [ ] 未保存の変更があっても ⌘Q で確認ダイアログは出ない（以前と同じ。変更はセッションに残る）
- [ ] 起動中にログアウト → ログアウトが「syki::sok が中断しました」で止まらない。再ログイン後、直前の入力が残っている
- [ ] 起動中に再起動 / システム終了 → 止まらない
- [ ] ファイル選択ダイアログ（画像の挿入など）を開いたまま Dock から「終了」→ 遅くとも 5 秒ほどで終了する
- [ ] 赤ボタン（隠す）→ Dock から「終了」でも終了し、ipc-session.json が消える
- [ ] `osascript -e 'quit app "syki::sok"'` はエラー -128（User canceled）を返すことがあるが、アプリは直後に終了する（想定どおり）

## 8. v2 ヘッダー・フッターのオーバーレイと自動非表示（P2。Chromium では確認済みの仕組みが WebKit で成り立つか）

窓の上端・下端のバーが本文の上に浮き、本文がその下をくぐる作りです（docs/design/v2-plan-P2.md）。Windows の WebView2 は実機で確認済み。WKWebView（Safari 15.6 まで）は未確認なので、次を見てください。

- [ ] 長いノートを一番下までスクロールすると、最後の行がフッターの**上**に出る（textarea の `padding-bottom` がスクロール範囲に入るか。入らずに最終行がフッターに隠れたままなら、textarea 自体に `margin-bottom: var(--ov-bottom)` を付ける案に切り替える）
- [ ] 矢印キー（↓ を押し続ける）で行を画面の下端へ動かしても、キャレットの行がフッターに隠れずスクロールして追従する（`scroll-padding-bottom` が効くか）。上端のヘッダーも同じ（↑）
- [ ] 日本語入力で変換を始めた瞬間にヘッダーとフッターが消える（`compositionstart`）。確定しても勝手に戻らない。マウスを数 px 動かすと戻る
- [ ] 英数字を打つと消え、ホイールでスクロールしても消える。**タブをクリックして別のノートに切り替えた直後にヘッダーが消えない**
- [ ] スクロールバーをつかんでドラッグすると消える。縦スクロールバーの上端・下端はバーの下に隠れる（つまみが上端・下端にあるときだけ。ホイールで動かせる）
- [ ] F6 で本文 → ヘッダー → 左のタブの帯 →（ノートを2つ並べているときは）右のタブの帯 →（画面を分けているときは）仕切り → フッター → 本文の順にフォーカスが動き、バーが出る。Esc で本文に戻る。Fn が必要な機種では、設定 → ショートカット →「本文・ヘッダー・ステータスバーを順に移動」で別のキーにできる
- [ ] 左端のタブの帯: 細い色の帯（6px）で、いま開いているノートが最も濃く、離れるほど薄い（5 段階: 100%、56%、44%、32%、20%。`rgb(r g b / max(…))` の透明度が WKWebView で効いているか）。ポインタを置いて 0.12 秒ほど待つと 200px に広がり、名前が読める（通り過ぎただけでは開かない）。本文は動かない
- [ ] ノートを2つ並べる（`⌘\`）と、右のページの右端にも帯が出る。スクロールバーの設定が「自動」（オーバーレイ）でも「常に表示」でも、帯がスクロールバーに重ならない（9px 以上離れる。測った幅は `--tab-scrollbar-w`）。帯のクリックは、その帯のページだけを切り替える
- [ ] タブを上下にドラッグして並べ替える（線が出る。Esc、または帯から離れて放すと元のまま）。開いた帯の × で閉じる。Option+クリックで右のページに開く。タブを右クリック →「横に開く」。テキストファイルを帯にドロップすると新しいノートになる
- [ ] 画面の読み上げ（VoiceOver）: 消えている間もステータスの文言（Saved など）が読み上げられる
- [ ] 分割表示: 右ペインの帯（ファイル名）がヘッダーの下に出る。HTML のプレビューはヘッダーとフッターの間に収まる
- [ ] 設定 → 外観 →「ヘッダーとステータスバー」の「うすい（半透明）」と「すりガラス（ぼかし）」: 切り替えると保存前に反映され、取り消しで戻る。**すりガラスで `-webkit-backdrop-filter` が効くか**（Safari 15.6 までは接頭辞付きだけ。効かなければ「うすい」と同じ見た目になる＝本文がぼけずにうっすら透けるだけで、壊れてはいない）。`opacity` の切り替え（自動非表示）のあいだ、ぼかしが消えたり描き直されなかったりしないか（崩れるなら `glass` のバーに `will-change: opacity` を付ける、それでも崩れるなら遷移を切る）。8 万行のノートでスクロールが重くならないか（`tools/perf/v2-p2-translucency.md` の Windows の数字と比べる。**Mac の既定は、これが済むまで「うすい」のまま**）
- [ ] 設定 →「入力中・スクロール中はヘッダーとステータスバーを隠す」をオフにすると、打っても動かしても二つのバーが出たまま（リスナーが 1 つも付かない）。オンに戻すと元の動き
- [ ] 行番号: 左の余白に、背景も縦の罫線もなく薄い文字で出る（紙・墨の両方で読める濃さ）。折り返した行は先頭の行にだけ番号が付き、結果ブロックの帯（左端の細い緑の縦線）と行番号の高さが本文の行とそろう。「行へ移動」で着地した行が、ヘッダーとフッターの間に出る
- [ ] Zen モード（`Ctrl+Cmd+Z`、`ui.set_view { zen }` でも）: 余白は消えず本文の左右が広がり、行番号は 30% の濃さに薄まる（マウスを載せると濃くなる）。バーは**マウスを動かしても戻らない**。窓の最上端（6px）か最下端に 150ms ポインタを止めると、そのバーだけが戻り、ポインタが離れて 0.7 秒で消える。`F6` でも出る。Mac では窓の最上端はメニューバーの下なので、**ポインタをそこまで持っていけるか**（全画面のとき、メニューバーが自動表示される動きと喧嘩しないか）を見る
- [ ] Zen モードで、ふつうのメッセージ（保存しました、など）はステータスバーに出ない（VoiceOver では読み上げられる）。**保存の失敗**（書き込めないフォルダのノートで `Cmd+S`）、設定の保存失敗、ディスク上の衝突、**録音中**は、Zen でもステータスバーが戻って文言が見える。メッセージが消えるとバーも消える
- [ ] 強制色（「コントラストを上げる」）と「透明度を下げる」（システム設定 → アクセシビリティ → ディスプレイ）をオンにすると、設定にかかわらずバーは不透明で、ぼかしが付かない

## 9. v2 ページの仕切り（P4。Chromium では確認済み。WKWebView は未確認）

2つのノートを左右に並べたときの仕切り（`#pane-resizer`）の見た目とキーボード操作です（docs/design/v2-plan-P4-P5.md）。Windows の WebView2 は実機で確認済み。ノドのドットの薄れ（`-webkit-mask-image`）と `rgb(r g b / a)` は Safari 15.4 / 12.1 から使える構文だけで書いてありますが、Mac では見ていません。

- [ ] `⌘\` でノートを2つ並べると、真ん中にノド（幅 24px。中央に影、両側へ薄れるドット）が出る。2つのページは同じ幅（ウィンドウ幅から 24px を引いた半分ずつ）。ドットが両端へ薄れていて、四角い帯に見えない（`-webkit-mask-image` が効いているか）
- [ ] 仕切りをドラッグすると左のページの幅が指に付いてくる（15%〜85%）。ダブルクリックで半分ずつに戻る
- [ ] **キーボード**: F6 を何度か押すと（本文 → ヘッダー → 左のタブの帯 → 右のタブの帯 → 仕切り）仕切りにフォーカスが来て、真ん中にアクセント色の縦線が出る。`←` `→` で 2 ポイント、`Shift` を足すと 10 ポイント、`Home` `End` で 15% / 85%、`Enter` で半分ずつ。`Esc` で本文に戻る。Mac のノート PC で `Home` `End` が無いときは `Fn` + `←` `→`。矢印を押したときにページがスクロールしたり、文字が入力されたりしない
- [ ] 設定 → 一般 → 外観 & ウィンドウ →「2つのページの仕切り」: 「影だけ」（ドットが消える）と「細い線」（5px の細い仕切りに 1px の線。2つのページが少し広がる）が、保存前に反映され、取り消しで戻る。保存して再起動しても残る。どの見た目でも、半分ずつのとき 2つのページが同じ幅
- [ ] プレビューを横に開く（`⌘⌥V`）と、仕切りは幅 6px のつかみしろだけになる（ページと机の色の段差が仕切り）。そのままドラッグと矢印キーで動く。「細い線」を選んでいると 1px の線だけが足される
